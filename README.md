# Historical Atlas

A spatiotemporal atlas and evidence ledger for chronicle applications. Historical names, populations, and coordinates link to their sources, with interpretations recorded as separate estimates.

## Usage

Requires Rust 1.97.1 or later with the `wasm32-unknown-unknown` target, the Protocol Buffers compiler (`protoc`), Python 3.12 or later, Poppler, and Tesseract with the English model for extraction tests. Image recognition of Chinese sources also uses the `chi_sim` model.

```sh
cargo run -p atlas-compile -- verify data
cargo run -p atlas-compile -- build data dist
cargo run -p atlas-compile -- derive data data/guizhou-1960s/bijie/communes.derive.json <new-output-directory>
cargo run -p atlas-compile -- register data controls.json registered.json
cargo run -p atlas-compile -- terrain-grid terrain-request.json <new-terrain.json>
cargo run -p atlas-compile -- trace data data/guizhou-1960s/zhijin/ertang.trace.json <new-output-directory>
cargo run -p atlas-compile -- boundary data <trace.json> <boundary-controls.json> <new-output-directory>
cargo run -p atlas-compile -- slice data <tt-ms> nominal <new-output-directory>
cargo run -p atlas-compile -- reconstruct data data/paleogeography/panxian-240ma.reconstruction.json <new-output-directory>
cargo run -p atlas-compile -- territory data data/guizhou-1960s/bijie/wuliping.territory.json <new-output-directory>
cargo run -p atlas-compile -- tiles data https://example.org/atlas/ 14 <new-output-directory>
sh scripts/ci.sh
```

Open a compiled publication in the desktop map with `cargo run -p atlas-app -- dist`. The map supports Earth, Moon, and Mars, place-name and former-name search, source hierarchy browsing, and the evidence ledger. Select a Gregorian year, a full Gregorian date (`YYYY-MM-DD`), an integer age in Ma before J2000, or exact TT milliseconds. Calendar inputs use the TT axis; uncertainty modes query the same timeline as `atlas-compile`. The default **Source-map places** layer displays positions registered from reviewed map symbols; selecting a point shows its sheet citation and positional allowance. **Printed coordinates** displays the original coordinate anchors, including their reporting precision; the selected-time layer filters those anchors by dated evidence. Clicking coincident points lists each entity separately.

Earth uses a bundled [Natural Earth II](https://www.naturalearthdata.com/downloads/50m-raster-data/50m-natural-earth-2/) physical basemap, with elevation hillshade over the Bijie–Zhijin–Liuzhi–Anshun area from [Mapzen Terrain Tiles](https://registry.opendata.aws/terrain-tiles/). SRTM and GMTED2010 elevation data are courtesy of the U.S. Geological Survey. Basemap tiles and font subsets load from `assets/` as separate files on desktop and in the browser. To regenerate it, install Python's `numpy` and `Pillow` packages and run `python3 tools/build-basemap.py <NE2_50M_SR_W.tif> <terrain-geotiff-directory> apps/atlas-app/assets/basemap`; `manifest.json` controls tile coverage, zooms, attribution, and fingerprints. Each tile may specify a `body` (default `earth`); adding regional tiles requires no Rust changes. `assets/fonts.json` lists the font files in fallback order. The application opens on a globe with rotation across the poles and pointer-anchored zoom. **Globe** returns to the world view; **Data extent** frames the mapped places on the selected body. **Source drawings** opens the traced map sheets with their measured settlement symbols and vector boundaries.

The optional **Terrain estimates** layer displays reconstructed boundaries with dashed outlines. `build` evaluates every `*.derive.json` recipe from cited place anchors, registered envelopes, elevation grids, and optional area/adjacency constraints. Each polygon links to its recipe and source comparisons. `derive` evaluates one recipe; unattainable constraints fail the build.

To render a static Bijie overview and a regional detail, install Python’s `matplotlib`, `numpy`, and `Pillow` packages and run `python3 tools/render-bijie.py <publication-directory> <output-directory> --detail haogou-commune liuhua-commune`. The renderer uses the bundled fonts and basemap, checks seed containment, and places commune labels without overlaps.

For the browser application, install Trunk and run `cd apps/atlas-app && trunk build --release`. Serve `dist/site` from the repository root over HTTP. Entity indexes carry geometry bounds and references; the browser loads verified geometry parts when zooming into a region or selecting a feature. Geometry and WASM parts are each smaller than 4 MB. Native and browser rendering use the pinned `maplibre-rs-experimental` dependency. The bundled Atlas CJK font is a subset of Noto Sans CJK SC under the [SIL Open Font License](apps/atlas-app/assets/OFL.txt). Rare characters use Atlas Han Supplement, a subset of [BabelStone Han](https://www.babelstone.co.uk/Fonts/Han.html) by Andrew West under the [Arphic Public License](apps/atlas-app/assets/ARPHICPL.TXT). To expand glyph coverage, install Python's `fonttools` package and run `python3 tools/subset-font.py <NotoSansCJK-SC-Regular.otf> --fallback-font <BabelStoneHan.ttf>`.

Attach a Chronicle event package with `?overlay=<package-url>`. Relative URLs resolve against the atlas page; cross-origin servers must allow browser access through CORS. Packages must be smaller than 4 MB. The desktop equivalent is `cargo run -p atlas-app -- dist --overlay data/overlays/apollo11.overlay.json`. The [Apollo 11 example](data/overlays/apollo11.overlay.json) is also available in the browser at `?overlay=overlays/apollo11.overlay.json`; click its event title to visit the landing site and time.

Curated records live in `data/`. Sources can identify print, maps, aerial photographs, satellite images, manuscripts, or datasets through `capture`, including a source-stated date, sortie/frame identifiers, and an archive repository/accession. Physical observations accept metre measurements, existence states, and `flows_into` relationships without requiring a name or demographic table fields. `scan_page` is one-based; `page_or_sheet` identifies the printed page. Online sources carry a URL and records identify the cited section or table in `locator`. `checked` records transcription review. Dates retain their source convention, and coordinates retain their stated datum and angular precision. Unresolved printed coordinates use `unresolved_coordinate`, preserving the notation and its explanation while `coordinate` stays null; they appear in evidence cards and are excluded from map points. Historical era concordances cite a calendar table and its query, retain lunar month and intercalation, and convert the full cited period to a bounded instant. Evidence cards show the civil-date range and offer a timeline link to its midpoint.

The `tiles` command publishes body-separated MVT layers for reviewed coordinates, registered map points, polygons, and linework, with TileJSON manifests, map styles, and the complete evidence index. Set `base-url` to the directory's final HTTP(S) address. `tiles/index.json` lists coordinate tilesets and `tiles/geometry.json` lists registered geometry tilesets; each tileset includes a sparse tile inventory. Points retain their record and entity UUIDs, original coordinate notation, source datum, reporting precision, and evidence URL. Dated geometry carries `valid_from` / `valid_to` and possible/certain endpoint bounds as exact TT millisecond strings. The end is exclusive. The display projection is spherical Mercator, with buffered tile edges and an explicit error for coordinates outside its latitude domain.

Time slices select dated names, hierarchy, demographics, physical measurements, and existence states. Boundary intervals are supplied as `validity` on traced or derived units; `slice.json` lists their selected GeoJSON chunks. Destroyed or demolished features are removed from the time view while their evidence remains accessible. Supply a signed decimal TT millisecond offset from J2000 and choose `nominal`, `possible`, or `certain`. The output includes `slice.json`, UUID shards under `slice/index/`, and the complete evidence index. Each selected value retains its interval, source-record links, uncertainty, and source disagreements. Competing values appear together with a conflict flag; different name languages occupy separate slots.

For page extraction, run `python3 tools/ocr-ingest/ingest.py --pdf <path> --pages 1:10 --output scratch/extraction`. The default engine reads the embedded text layer. Use `--engine tesseract --languages chi_sim --tessdata-dir <models>` for image recognition; `--jobs 4` processes four pages concurrently. Extraction drafts include normalized text boxes, scan fingerprints, and recognition settings for page review; rerunning the command resumes the same batch.

Group extracted table cells with `python3 tools/ocr-ingest/tables.py scratch/extraction scratch/tables --profile bijie`. Profiles are available for Bijie, Anshun, and Liuzhi. Other layouts use `--profile-file <layout.json>` with `columns` entries `[field, left, right]` in normalized page coordinates, an `anchor_pattern`, and a `header_pattern`; the first column anchors the rows. Table drafts retain the text boxes and mark fields that need review.

Sheet registration accepts a `RegistrationJob` JSON document with a catalogued source, raster dimensions, target CRS and units, optional geographic `datum`, referenced control points, independent check points, and traced vertices. Use a scan page for paginated sources, or omit it for an unpaginated image identified by `capture.sha256`. Source coordinates use image pixels measured from the top-left corner. Each control must cite checked ledger facts through `basis` or, through `reference_sha256`, the SHA-256 of the catalogued reference raster or dataset its target was measured on; that source must carry a `rights` statement. `uncertainty` states a control's identification uncertainty in target units. Choose `{"kind":"affine"}`, `{"kind":"thin_plate","smoothing":0.0}`, or `{"kind":"projective"}`. The projective method fits a homography for oblique photographs of level ground from at least four controls and rejects vertices outside the convex hull of its controls or beyond the image horizon. `{"kind":"camera"}` resects a pinhole camera against a `terrain` grid for photographs over relief; it requires WGS84 longitude and latitude targets, a catalogued terrain source with rights, and fingerprinted terrain tiles. The focal length is estimated unless `focal_px` is supplied, and fits whose focal length is not determined by the controls, as in near-vertical views, are refused. `terrain-grid` builds that `terrain` object from downloaded Terrain Tiles GeoTIFFs: the request names the catalogued `source_id`, longitude–latitude `bounds` as west, south, east and north, each tile's public `url` and local `path`, and an optional `water_surface_m` for tiles that include seafloor. The output records each tile's SHA-256 with the cropped grid. The result's `camera` section reports the focal length, optical centre, heading, depression and roll, and pixel residuals at controls and check points; vertices are projected onto the terrain. The result includes the scan fingerprint, transformed vertices, and residuals in the declared target units. See `atlas_compile::registration` in the generated Rust API documentation for the input fields. `*.places.json` documents link measured symbols to checked map records and same-entity table coordinates. `build` fits their controls, evaluates their holdouts, publishes registration details under `maps/`, and includes separate `map_location` estimates in the entity shards. Boundary traces sharing that source, scan page, and full-page raster dimensions use the same fitted transformation and appear on the geographic map. Use `registration_id` on a trace to select among multiple registrations of the same page. Place maps accept the same methods. Boundaries retain the controls' datum and registration allowance; selecting one displays both alongside the source's boundary-construction method.

The `trace` command validates a `SheetTrace` and publishes polygon rings and open linework in source pixels. `lines` contain cited `record_id`, component `paths`, and optional `validity`; each path indexes the shared vertices. Rings reference a shared vertex array; each unit cites a checked record on the traced sheet. `boundary_method` records `surveyed`, `compiled_from_places`, or `unstated`, with checked `method_basis` records for stated methods. `verify` also checks every `*.trace.json` in the data directory. `build` publishes these drawings as geometry parts referenced by the entity indexes; `places` link measured symbol centers to checked records on the same sheet. The Ertang example traces the commune outline on printed page 32 and cites the edition's boundary-construction explanation.

The `boundary` command takes a target CRS, affine or thin-plate method, referenced controls, independent check points, and positive `maximum_segment_pixels`. It densifies shared polygon edges and open line segments before transformation and validates polygon topology. Results retain source geometry, residuals, datum, and evidence. Geographic rings crossing the antimeridian require split components. Boundary `validity` retains endpoint uncertainty; dated outlines appear in the selected-time view, with possible membership shown as a dashed outline.
