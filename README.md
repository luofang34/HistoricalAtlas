# Historical Atlas

A spatiotemporal atlas and evidence ledger for chronicle applications. Historical names, populations, and coordinates link to their sources, with interpretations recorded as separate estimates.

## Usage

Requires Rust 1.97.1 or later with the `wasm32-unknown-unknown` target, the Protocol Buffers compiler (`protoc`), Python 3.12 or later, Poppler, and Tesseract with the English model for extraction tests. Image recognition of Chinese sources also uses the `chi_sim` model.

```sh
cargo run -p atlas-compile -- verify data
cargo run -p atlas-compile -- build data dist
cargo run -p atlas-compile -- derive data data/guizhou-1960s/bijie/communes.derive.json <new-output-directory>
cargo run -p atlas-compile -- register data controls.json registered.json
cargo run -p atlas-compile -- trace data data/guizhou-1960s/zhijin/ertang.trace.json <new-output-directory>
cargo run -p atlas-compile -- boundary data <trace.json> <boundary-controls.json> <new-output-directory>
cargo run -p atlas-compile -- slice data <tt-ms> nominal <new-output-directory>
cargo run -p atlas-compile -- reconstruct data data/paleogeography/panxian-240ma.reconstruction.json <new-output-directory>
cargo run -p atlas-compile -- territory data data/guizhou-1960s/bijie/wuliping.territory.json <new-output-directory>
cargo run -p atlas-compile -- tiles data https://example.org/atlas/ 14 <new-output-directory>
sh scripts/ci.sh
```

Open a compiled publication in the desktop map with `cargo run -p atlas-app -- dist`. The map supports Earth, Moon, and Mars, place-name and former-name search, source hierarchy browsing, and the evidence ledger. Select a Gregorian year, an integer age in Ma before J2000, or exact TT milliseconds. The 1950–1984 slider and uncertainty modes query the same timeline as `atlas-compile`. The default **Source-map places** layer displays positions registered from reviewed map symbols; selecting a point shows its sheet citation and positional allowance. **Printed coordinates** displays the original coordinate anchors, including their reporting precision; the selected-time layer filters those anchors by dated evidence. Clicking coincident points lists each entity separately.

Earth uses a bundled [Natural Earth II](https://www.naturalearthdata.com/downloads/50m-raster-data/50m-natural-earth-2/) physical basemap, with elevation hillshade over the Bijie–Zhijin–Liuzhi–Anshun area from [Mapzen Terrain Tiles](https://registry.opendata.aws/terrain-tiles/). SRTM and GMTED2010 elevation data are courtesy of the U.S. Geological Survey. The basemap works offline. To regenerate it, install Python's `numpy` and `Pillow` packages and run `python3 tools/build-basemap.py <NE2_50M_SR_W.tif> <terrain-geotiff-directory> apps/atlas-app/assets/basemap`; `manifest.json` records tile coordinates, source URLs, and fingerprints. The application opens on a globe with rotation across the poles and pointer-anchored zoom. **Globe** returns to the world view; **Guizhou** frames the study area. **Source drawings** opens the traced map sheets with their measured settlement symbols and vector boundaries.

Search for `毕节县` to view its registered county outline, or a place such as `二塘公社` or `陈家桥` to open its source drawing. Selecting a registered boundary fits its full outline to the map viewport. Switch between **Source drawing** and **Geographic map**, and click a settlement symbol to inspect its evidence; coincident administrative seats remain separately selectable.

The optional **Terrain estimates** layer shows reconstructed boundaries with dashed outlines and translucent fills. `build` evaluates the `*.derive.json` recipes, using cited commune and subordinate-place coordinates as seeds, a registered county outline as the enclosing polygon, and cropped elevation cells from Terrain Tiles. The four-neighbor travel cost combines ground distance with weighted elevation change. Optional `area_constraint` entries cite a checked territory record and set an absolute fitting tolerance in square kilometres. The solver establishes the adopted adjacencies through terrain-cost connections, adjusts additive seed costs, then resolves remaining area steps by transferring boundary cells along low-cost terrain edges. Transfers must reduce the combined area residual while preserving those adjacencies, seed membership, and connected regions. An `unresolved_neighbors` entry retains a conflicting source adjacency, its checked supporting records, and the geometric comparison without imposing that adjacency on the fit. Unattainable constraints fail the build. Each reconstruction links to its complete recipe under `derived/`, including source tile fingerprints, the coordinate-alignment assumption, and excluded seed records. `derive` evaluates one recipe. Selecting a reconstructed commune frames its extent and displays its input evidence, including area and shared-edge comparisons with checked overview descriptions.

To render a static Bijie overview and a regional detail, install Python’s `matplotlib`, `numpy`, and `Pillow` packages and run `python3 tools/render-bijie.py <publication-directory> <output-directory> --detail haogou-commune liuhua-commune`. The renderer uses the bundled fonts and basemap, checks seed containment, and places commune labels without overlaps.

For the browser application, install Trunk and run `cd apps/atlas-app && trunk build --release`. Serve `dist/site` from the repository root over HTTP; the build includes the evidence shards and divides the WASM module into checked parts smaller than 4 MB. Native and browser rendering use the pinned `maplibre-rs-experimental` dependency. The bundled Atlas CJK font is a subset of Noto Sans CJK SC under the [SIL Open Font License](apps/atlas-app/assets/OFL.txt). Rare characters use Atlas Han Supplement, a subset of [BabelStone Han](https://www.babelstone.co.uk/Fonts/Han.html) by Andrew West under the [Arphic Public License](apps/atlas-app/assets/ARPHICPL.TXT). To expand glyph coverage, install Python's `fonttools` package and run `python3 tools/subset-font.py <NotoSansCJK-SC-Regular.otf> --fallback-font <BabelStoneHan.ttf>`.

Attach a Chronicle event package with `?overlay=<package-url>`. Relative URLs resolve against the atlas page; cross-origin servers must allow browser access through CORS. Packages must be smaller than 4 MB. The desktop equivalent is `cargo run -p atlas-app -- dist --overlay data/overlays/apollo11.overlay.json`. The [Apollo 11 example](data/overlays/apollo11.overlay.json) is also available in the browser at `?overlay=overlays/apollo11.overlay.json`; click its event title to visit the landing site and time.

Event packages contain `version: 1`, a `title`, and `events`. Each event has a unique `id`, a plain-text `title`, an `entities` list of atlas UUIDs, a `validity` interval, and optional `description` and HTTP(S) `url` fields. Interval endpoints use the atlas's string-encoded TT milliseconds and an exclusive end; null endpoints retain unknown dates. Event markers follow the applied time and uncertainty selection, resolve published entity aliases, and preserve the source coordinates and precision of each anchor. Clicking an event selects its place and nominal starting time. Events without coordinate evidence remain accessible in the event panel.

Curated records live in `data/`. `scan_page` is one-based; `page_or_sheet` identifies the printed page. Online sources carry a URL and records identify the cited section or table in `locator`. `checked` records transcription review. Dates retain their source convention, and coordinates retain their stated datum and angular precision. Unresolved printed coordinates use `unresolved_coordinate`, preserving the notation and its explanation while `coordinate` stays null; they appear in evidence cards and are excluded from map points. Historical era concordances cite a calendar table and its query, retain lunar month and intercalation, and convert the full cited period to a bounded instant. Evidence cards show the civil-date range and offer a timeline link to its midpoint.

The `tiles` command publishes reviewed coordinate observations as body-separated MVT layers, TileJSON manifests, map styles, and the complete evidence index. Set `base-url` to the directory's final HTTP(S) address. `tiles/index.json` lists the available bodies; each tileset includes a sparse tile inventory. Points retain their record and entity UUIDs, original coordinate notation, source datum, reporting precision, and evidence URL. Dates remain source expressions; the time-slice indexes supply dated interpretations. The display projection is spherical Mercator, with buffered tile edges and an explicit error for coordinates outside its latitude domain.

The `territory` command produces a `territory.json` manifest and the evidence index. The manifest lists node arrays, relationship arrays, and GeoJSON feature collections under `territory/`, each smaller than 4 MB. A request selects an `entity_id` and a `scope`: `{"kind":"source","source_id":"bijie-gazetteer"}` for one edition's hierarchy, or `{"kind":"time","at":"<tt-ms>","selection":"nominal"}` for dated hierarchy estimates. Node networks retain subordinate and seat relationships, alternative claims, unlocated members, and each coordinate's original precision. Units without coordinates can use an explicitly cited seat as their drawing anchor. The map's **Territory nodes** toggle draws the selected place's network with dashed links; its source and selected-time views use the same queries as the compiler. Time selection applies to hierarchy assertions while node positions remain source coordinate observations.

Time slices select dated name, hierarchy, and demographic estimates. Supply a signed decimal TT millisecond offset from J2000 and choose `nominal`, `possible`, or `certain`. The output includes `slice.json`, UUID shards under `slice/index/`, and the complete evidence index. Each selected value retains its interval, source-record links, uncertainty, and source disagreements. Competing values appear together with a conflict flag; different name languages occupy separate slots.

Entity slices also contain `origins`: evidence that formation or establishment had occurred by the selected time. Origin dates distinguish bounded estimates, latest-formation limits, and approximate ages with unquantified uncertainty. Nominal mode uses the representative date; possible and certain modes evaluate the supplied constraints. Later survival is described by separate temporal properties. Lunar records retain the geological age convention and the dated UTC-to-TT conversion used for Apollo 11.

Plate reconstruction requests select a TT epoch, a model, an anchor plate, and pairs of coordinate records and plate-assignment estimates. Model excerpts in `*.plates.json` retain the source fingerprint, attribution, reference frame, and original rotation-file line numbers. The output includes `reconstruction.json`, the model under `plates/`, and the evidence index. Each derived position retains its original coordinate notation and datum alongside the resolved rotation circuit. The Panxian example uses the Merdith model's South China circuit at 240 Ma; its excerpt covers 0–250 Ma. Geological query ages use Julian million years before the model's declared present epoch.

For page extraction, run `python3 tools/ocr-ingest/ingest.py --pdf <path> --pages 1:10 --output scratch/extraction`. The default engine reads the embedded text layer. Use `--engine tesseract --languages chi_sim --tessdata-dir <models>` for image recognition; `--jobs 4` processes four pages concurrently. Extraction drafts include normalized text boxes, scan fingerprints, and recognition settings for page review; rerunning the command resumes the same batch.

Group extracted table cells with `python3 tools/ocr-ingest/tables.py scratch/extraction scratch/tables --profile bijie`. Profiles are available for Bijie, Anshun, and Liuzhi. Table drafts retain the text boxes and mark fields that need review.

Sheet registration accepts a `RegistrationJob` JSON document with a catalogued source, scan page, full-page raster dimensions, target CRS and units, referenced control points, independent check points, and traced vertices. Source coordinates use image pixels measured from the top-left corner. Choose `{"kind":"affine"}` or `{"kind":"thin_plate","smoothing":0.0}`. The result includes the scan fingerprint, transformed vertices, and residuals in the declared target units. See `atlas_compile::registration` in the generated Rust API documentation for the input fields. `*.places.json` documents link measured symbols to checked map records and same-entity table coordinates. `build` fits their controls, evaluates their holdouts, publishes registration details under `maps/`, and includes separate `map_location` estimates in the entity shards. Boundary traces sharing that source, scan page, and full-page raster dimensions use the same affine fit and appear on the geographic map. Each sheet must have a single place-map registration. Boundaries retain the controls' datum and registration allowance; selecting one displays both alongside the source's boundary-construction method.

The `trace` command validates a `SheetTrace` and publishes its closed polygon rings in source pixels. Rings reference a shared vertex array; each unit cites a checked record on the traced sheet. `boundary_method` records `surveyed`, `compiled_from_places`, or `unstated`, with checked `method_basis` records for stated methods. `verify` also checks every `*.trace.json` in the data directory. `build` includes these drawings in the entity shards; `places` link measured symbol centers to checked records on the same sheet. The Ertang example traces the commune outline on printed page 32 and cites the edition's boundary-construction explanation.

The `boundary` command adds a `BoundaryRegistration`: `target_frame`, `method`, `controls`, `check_points`, and a positive `maximum_segment_pixels`. It subdivides shared edges before registration and checks source and transformed topology, including self-intersections, holes, disconnected interiors, and overlapping multipolygon components. Outputs retain the original trace, sampled vertices, control references, residuals, and target CRS in files smaller than 4 MB. Earth output in `OGC:CRS84` with `degrees` also includes GeoJSON; other declared frames retain planar coordinates. Geographic rings crossing the antimeridian require split components. `surveyed_polygon` requires a cited survey method; other source-map outlines use `mapped_polygon`. Fit residuals measure registration quality, while the source's boundary-construction method remains separately recorded. Open the boundary output directory in the app to display registered outlines over the physical basemap. Click an outline to select its entity and inspect the source method and citation; search also centers on registered boundaries. These outlines appear in both source-browsing views. Boundary validity stays unknown until dated boundary evidence is available, so undated outlines are excluded from the selected-time view.
